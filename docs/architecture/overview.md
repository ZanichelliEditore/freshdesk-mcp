## Components

### Tooling & process

- **`AGENTS.md`** — the contract every contributor (human or AI) works from: the navigation map, the command surface, and the four execution principles.
- **`docs/`** — `architecture/` (this map, reflecting the active RFCs) and `rfc/` (the decision lifecycle `proposed/` → `active/` → `superseded/`/`retired/`).
- **`tools/checks/`** — scripts that enforce the RFC/docs conventions mechanically (e.g. keeping each RFC in the folder its Status names).
- **Quality gate** — linters/formatters wired at the pre-commit, command-surface, and CI layers so violations are caught mechanically.
- **CI** (`.github/workflows/`) — `quality.yml`: the quality gate plus a secrets + dependency scan on every push/PR. `release.yml` (RFC 2026-11-25, release on npm): on a `v*` tag, copies of those jobs, a fresh build packed once, then `npm publish` of that tarball by npm trusted publishing (OIDC, environment `npm`, no token); `workflow_dispatch` runs the chain and a `--dry-run` only.

- **`src/client/errors.ts`** — the one normalised error shape (SPEC §7.1): maps an HTTP status or a network failure to seven codes, with a documented fallback.
- **`src/client/rate-limit.ts`** — the rate limiter (SPEC §7.2): a budget read from the response headers, with a reserve for expensive operations, a floor, pacing and the hold after a 429; it owns every wait, bounded at 15 s per call or by the caller's shorter bound, and refuses with `rate_limited`. Called by the HTTP core around every request. Its options and state are `#` private fields: an assignment through a cast adds a property nothing reads, so a refusal is not loosened (tested field by field, and for the `#` helpers `expire`, `below` and `left`). The instance is not frozen: `acquire` and `observe` can still be shadowed on it, by its only holder, the client. `reserveRefusal()` reads, without a call (no token, no pacing, no state changed), the refusal an `expensive` `acquire` would meet now for being below the reserve, the same error (below the floor it still gives that refusal, where `acquire` would apply the floor rule first: it errs closed); the client passes it on as `http.reserveRefusal()`, the one view of the limiter's state a tool gets (T-035).
- **`src/client/http.ts`** — the HTTP core (SPEC §7.1): the one send function. Basic auth and UA, `https` on the default port to exactly the configured host (checked at construction and on every URL), redirects not followed, each status mapped to its error code, the limiter acquired before and fed after, stderr limited to method, path template, status and duration, each attempt cut off after 10 s. On top of that one function: `requestWithRetry` (a GET is retried on 429, 5xx and network errors, at most 3 times with backoff; any other method on 429 only, so a write is never applied twice; the whole call ends within 30 s, with a limiter wait that would reach the deadline refused as `rate_limited` and a GET in flight at it aborted as `network`; a write is not started with less than 10 s left, so the deadline never cuts one in flight, only its own timeout: it is refused as `rate_limited`, `retryable: true`, not sent, checked before the limiter is asked, in the bound the limiter is given and again after it (T-014); `http.reachedDeadline(error)` is true for an error the deadline ended, a mark only the client sets (a private `WeakSet`, so the error's shape is unchanged): a GET's expiry, and a GET's `network` failure that no retry can follow before the deadline (an attempt started at 19.6 s times out at 29.6 s; T-059), never one that used its retries with time left, a 5xx or a write's failure; a caller's deadline, optional, can only shorten the 30 s, and one already reached sends nothing) and `paginate` (follows `Link` to the caller's cap of pages and items, every page URL through the host check; given a deadline, all its pages share it and a page it cuts or does not ask for is a failed page, not a short list; with none each page gets its own 30 s; its return value says whether a cap cut the list and how many attempts it sent). `requestWithRetry`'s result carries `attempts`, the attempts it sent: one counts when `request` handed it to `fetch`, whatever came back (one cut in flight by a deadline included), and not when it was refused first (URL, deadline, limiter); `request` keeps the results it got through `fetch` in a private `WeakSet`, so a subclass's override that answers without calling it, or returns anything but the object it returned (a copy included), counts nothing for that attempt. The host, the limiter, the key, the dispatcher and the URL helpers are `#` private members and the instance is frozen: an assignment through a cast to any of them, or to a method, throws a `TypeError`, and requests still go to the configured origin only (tested). The threat model is a tool's mistake or a cast, not hostile code in the process: the prototype is not frozen and `process.env` keeps the key. A subclass gets no instance fields of its own: the base freezes the instance in its constructor, so a public field throws, and a `#` field depends on engines still allowing a private field on a frozen object (the "nonextensible applies to private" proposal would refuse it).

- **`src/schema/input.ts`** — `ticketInput` (SPEC §7.3): a tool's `{field: value}` turned into a Freshdesk API v2 ticket body (default fields under their ticket key, custom ones under `custom_fields`). A field by its exact API name or its label (trimmed, NFC, any case); a key naming two fields (shared label, or one's API name and another's label) is refused. A dropdown, ticket-type, status, priority, source, agent or group value by its name (exact, else the one choice that folds alike; a name two ids share refused, listing the ids; an agent or group name, even an exact one, also checked, folded, against the schema's agents or groups list, any other id there making it ambiguous and a truncated list refusing it as `incomplete_list`, T-041) or, for the last five, an id they have (agent and group: an id among their name → id `choices`, none without choices); a nested field as an `A > B > C` path checked level by level, levels not given sent as `null`; a field of any other type with a list of choices checked against it, with choices of another shape refused, with none passed through (requester ids, text); a product's name → id record is such another shape, so `product` stays refused. Unknown, ambiguous or repeated fields, two keys landing on one ticket key and invalid choices all come back in one `validation` error (`http_status: null`), one `errors[]` entry per input key, an invalid choice listing the valid ones at the failing level, all clipped to the `errors.ts` caps. Every call takes an allow set (`FieldSet`: default fields by API name, `custom` true or false), required, with no default (T-065): a field outside it is refused as `field_not_writable`, naming what the set allows, before its value is looked at; a missing or malformed set throws a `TypeError`. The set is a plain value: `src/schema` does not import `src/core` (`test/schema/input.test.ts`, "ticketInput: allow sets").
- **`src/schema/index.ts`, `output.ts`** — the schema service (SPEC §7.3): `SchemaService.get()` loads the ticket fields, then agents and groups as id → name maps (an agent's id and name only; a list's `truncated` kept), once per TTL given by the caller (`limits.schema_ttl_s`, through `src/tools/context.ts`; a clock gone back counts as expired), shared by concurrent callers and frozen, the two name maps as a `FrozenMap` that has no method to change it (class and prototype frozen); a failed load is returned and not cached. The cache, the load in flight and the TTL are `#` private fields and the service is frozen: an assignment through a cast throws a `TypeError` and changes neither what `get()` returns nor when it loads (tested). One load ends within 30 s, its three lists under one deadline: at it the request in flight is cut and no other is started, and the error is the client's (`network`, retryable; `rate_limited` for a limiter wait that would reach it). A loaded result carries `attempts`: the requests that load sent, retries included (the three lists' `attempts` added up), for the call that started the load, and 0 for a call served from the cache or joining a load in flight, so a load is counted once; a failed load reports none (T-056). Every result handed out is frozen (a failed one with its error), so the call that started a load cannot swap what the calls that joined it get. A load started by `get_ticket_schema` (which has no `api_calls_used`), by a `get_ticket` call that then fails, or a load that fails, is reported by no call's `api_calls_used`; the limiter still sees every request. `ticketOutput` turns a raw ticket into `{label: value}`: status, priority, source, agent and group as names (the rule picked by the field's `type`), a nested field as one `A > B > C` path, an unresolvable id named rather than guessed (and an id missing from a truncated list said to be not loaded), fields hidden by the team config (label, API name or ticket key, trimmed, NFC, any case) left out; requester, company and product as raw ids.

- **`src/core/write-path.ts`** — the write path, the project's safety core (RFC [`2026-11-25-write-safety-core`](../rfc/active/2026-11-25-write-safety-core.md), AGENTS.md hard rule 1; T-064): the one path every request other than GET takes to Freshdesk. `createWritePath(options)` (the team `limits` and `toolsets` among them) builds the one `HttpClient` on the one `RateLimiter` (the team `limits`) and keeps it in a closure; it hands out only `view`, a `GetView` on that client (invariant 1). The resource modules and the schema service take `GetHttp`. On no place's list in `eslint.tool-imports.json`: under `src/tools/`, only `context.ts`, exempt as the file that builds the context, imports it (`test/lint-rules.test.ts`). Outside `src/core/**`, eslint fences keep the core the one holder of a client that can write and the one source of an allow set (T-077, `eslint.config.mjs` `coreFences`, `test/lint-rules.test.ts` "the client, the limiter, ticketInput and createWritePath stay in the core"): in `src/**` and `scripts/**` a value import of `HttpClient`, `RateLimiter` or `SmokeClient` (named, aliased, re-exported, or the module by `import *`, `export *` or a literal dynamic `import()`) and a `new HttpClient(` or `new RateLimiter(` are refused, type imports pass, exempt exactly `src/client/http.ts`, `src/client/rate-limit.ts` and `scripts/smoke/smoke.ts` (`SmokeClient`); an import of `ticketInput` is refused outside `src/schema/input.ts`; `createWritePath` may be imported or called only by `src/tools/context.ts` (that it passes the team file's `toolsets` holds by inspection, not by lint); in `src/core/**` every re-export (`export … from`, `export *`, an `export { … }` list) is refused, an exempt defining module, `smoke.ts` and `context.ts` have no re-export and no value export list (`export { c }`, `export *`), so none passes on what it holds under another name. In `src/tools/**` the allow-list refuses these imports and the syntax rule the `new` and the call. Not claimed: a non-literal import source, a symlink, an exported declaration holding the value, `.constructor`, a computed member, `Reflect.construct`. The write entries (invariants 2, 3, 5, 6; T-068): `entries`, present only when `write` is in `toolsets` (with it absent, `send` alone included, the key is absent), one frozen entry per write tool keyed by entry point: `update_ticket.update`, `categorize_tickets.update`, `hand_off_draft.note` and `.assign`, `add_note.note`. A ticket entry builds its body through `ticketInput` with its own allow set (no input names a set), refuses `field_not_writable` with nothing sent, then refuses a body whose top-level keys are not those its set's fields map to (`custom_fields` with custom fields, `tags` for `update_ticket`, whose entry alone reads `tags`, a whole list of strings, copied once then checked): the schema is the tool's, so a forged one still cannot send another key. A change that sets nothing is refused. A note entry takes `{ id, body, notify?, deadline? }`, `body` a string, and sends `{ body, private: true }` built here, plus `notify_emails` when `notify` names agents, so `private: false`, `user_id`, `incoming`, attachments, a caller's own `notify_emails` or anything else never reach Freshdesk. Notify (invariant 4; T-069): `notify` is a list of agent ids, copied once, each a positive safe integer, de-duplicated, then capped at `NOTIFY_CAP` (10, OD-14), refused before any request otherwise (an invalid ticket id too, so it spends no lookup); each distinct id is looked up with `getAgent` through the GET-only view, one GET each, in order, stopping at the first that fails; the whole note is refused, no POST, on a failed lookup (404, 5xx, timeout, `rate_limited`), an agent not clearly active (fail closed), or an email that is null, empty or not one plain address (one `@`, a dot in the domain, no space, control or format character (`\p{Cc}`, `\p{Cf}`) and none of `,;<>"()[]:\`); a `deadline` that is not a number is refused too, so the entry resolves. No ids sends no GET and no `notify_emails` key. The core keeps no address after the call; not claimed: that none reaches the caller, since the note's answer is passed back as Freshdesk sends it and may echo the recipients (the tool must not return them, `docs/improvements.md`) (`test/core/notify.test.ts`). An entry never rejects: every refusal, an input that throws when read included, is `validation`, `http_status: null`, `attempts: 0` (`test/core/entries.test.ts`). The entries are handed to the write tools by `src/tools/toolsets/write/index.ts` (T-071).
