## Components

### Tooling & process

- **`AGENTS.md`** — the contract every contributor (human or AI) works from: the navigation map, the command surface, and the four execution principles.
- **`docs/`** — `architecture/` (this map, reflecting the active RFCs) and `rfc/` (the decision lifecycle `proposed/` → `active/` → `superseded/`/`retired/`).
- **`tools/checks/`** — scripts that enforce the RFC/docs conventions mechanically (e.g. keeping each RFC in the folder its Status names).
- **Quality gate** — linters/formatters wired at the pre-commit, command-surface, and CI layers so violations are caught mechanically.
- **CI** (`.github/workflows/`) — the quality gate plus a secrets + dependency scan on every push/PR.

- **`src/client/errors.ts`** — the one normalised error shape (SPEC §7.1): maps an HTTP status or a network failure to seven codes, with a documented fallback.
- **`src/client/rate-limit.ts`** — the rate limiter (SPEC §7.2): a budget read from the response headers, with a reserve for expensive operations, a floor, pacing and the hold after a 429; it owns every wait, bounded at 15 s per call or by the caller's shorter bound, and refuses with `rate_limited`. Called by the HTTP core around every request. Its options and state are `#` private fields: an assignment through a cast adds a property nothing reads, so a refusal is not loosened (tested field by field, and for the `#` helpers `expire`, `below` and `left`). The instance is not frozen: `acquire` and `observe` can still be shadowed on it, by its only holder, the client.
- **`src/client/http.ts`** — the HTTP core (SPEC §7.1): the one send function. Basic auth and UA, `https` on the default port to exactly the configured host (checked at construction and on every URL), redirects not followed, each status mapped to its error code, the limiter acquired before and fed after, stderr limited to method, path template, status and duration, each attempt cut off after 10 s. On top of that one function: `requestWithRetry` (a GET is retried on 429, 5xx and network errors, at most 3 times with backoff; any other method on 429 only, so a write is never applied twice; the whole call ends within 30 s, with a limiter wait that would reach the deadline refused as `rate_limited` and an attempt in flight at it aborted as `network`; a caller's deadline, optional, can only shorten the 30 s, and one already reached sends nothing) and `paginate` (follows `Link` to the caller's cap of pages and items, every page URL through the host check; given a deadline, all its pages share it and a page it cuts or does not ask for is a failed page, not a short list; with none each page gets its own 30 s; its return value says whether a cap cut the list). The host, the limiter, the key, the dispatcher and the URL helpers are `#` private members and the instance is frozen: an assignment through a cast to any of them, or to a method, throws a `TypeError`, and requests still go to the configured origin only (tested). The threat model is a tool's mistake or a cast, not hostile code in the process: the prototype is not frozen and `process.env` keeps the key. A subclass gets no instance fields of its own: the base freezes the instance in its constructor, so a public field throws, and a `#` field depends on engines still allowing a private field on a frozen object (the "nonextensible applies to private" proposal would refuse it).
- **`src/client/resources/ticket-fields.ts`** — `listTicketFields` (SPEC §7.3): one `GET /ticket_fields` through `requestWithRetry` (the caller's deadline, if any, passed on), the body checked by a zod schema that passes unknown keys through (choices as a list, a 2- or 3-level tree, status names or ids); a body in any other shape is `server` with the real status and a message that quotes nothing from it.
- **`src/client/resources/agents.ts`, `groups.ts`** — `listAgents`, `listGroups` (SPEC §7.3): every page of `GET /agents` and `GET /groups` (100 per page, at most 10 pages) through `list-all.ts`, which hands the caller's deadline, if any, to `paginate` and checks each page with a zod schema before asking for the next (an agent's whole-number `id` and non-empty `contact.name`, a group's `id` and `name`; unknown keys passed through); a page in any other shape is `server` with its real status, a message that quotes nothing from it, and no further page asked for; a list the 10-page cap cut comes back with `truncated: true`.
- **`src/schema/input.ts`** — `ticketInput` (SPEC §7.3): a tool's `{field: value}` turned into a Freshdesk API v2 ticket body (default fields under their ticket key, custom ones under `custom_fields`). A field by its exact API name or its label (trimmed, NFC, any case); a key naming two fields (shared label, or one's API name and another's label) is refused. A dropdown, ticket-type, status, priority or source value by its name (exact, else the one choice that folds alike; a name two ids share refused) or, for the last three, an id they have; a nested field as an `A > B > C` path checked level by level, levels not given sent as `null`; a field of any other type with a list of choices checked against it, with choices of another shape refused, with none passed through (agent, group, requester ids, text). Unknown, ambiguous or repeated fields, two keys landing on one ticket key and invalid choices all come back in one `validation` error (`http_status: null`), one `errors[]` entry per input key, an invalid choice listing the valid ones at the failing level, all clipped to the `errors.ts` caps.
- **`src/schema/index.ts`, `output.ts`** — the schema service (SPEC §7.3): `SchemaService.get()` loads the ticket fields, then agents and groups as id → name maps (an agent's id and name only; a list's `truncated` kept), once per TTL given by the caller (`limits.schema_ttl_s`, through `src/tools/context.ts`; a clock gone back counts as expired), shared by concurrent callers and frozen, the two name maps as a `FrozenMap` that has no method to change it (class and prototype frozen); a failed load is returned and not cached. The cache, the load in flight and the TTL are `#` private fields and the service is frozen: an assignment through a cast throws a `TypeError` and changes neither what `get()` returns nor when it loads (tested). One load ends within 30 s, its three lists under one deadline: at it the request in flight is cut and no other is started, and the error is the client's (`network`, retryable; `rate_limited` for a limiter wait that would reach it). `ticketOutput` turns a raw ticket into `{label: value}`: status, priority, source, agent and group as names (the rule picked by the field's `type`), a nested field as one `A > B > C` path, an unresolvable id named rather than guessed (and an id missing from a truncated list said to be not loaded), fields hidden by the team config (label, API name or ticket key, trimmed, NFC, any case) left out; requester, company and product as raw ids.
- **`src/tools/context.ts`** — `createContext(config, dispatcher)` (SPEC §7.3, §10): the one place a `Config` becomes what the tools work with: the HTTP client, on a rate limiter it alone holds, built from the team `limits` (domain, key and override from the config, the dispatcher from the caller), the schema service with `limits.schema_ttl_s` as its TTL, the team settings as its own deep-frozen copy, and `ticketOutput` with the team `fields` already given. The context holds `http`, `schema`, `team` and `ticketOutput`, not the limiter: a tool meets the limits only through `http`, as `rate_limited`. The context object, the client and the schema service are frozen and have no own properties; this guards against a tool's mistake or a cast, not against hostile code in the process. Not covered: `context.http.constructor` and `context.schema.constructor` reach the classes, from which a tool could build its own client or service, and the lint block below does not refuse it. A tool takes the context, never the config: an eslint block for `src/tools/**` (this file exempt) refuses a value import of the config, the client, the schema service or `ticketOutput`, a path not in its shortest form, and any dynamic `import()`, in the forms its tests list; known gap: a segment starting with a dot followed by `..` (`../.x/../config.js`) still reaches `config`, to be closed by an allow-list of shortest-form specifiers (PLAN, proposed row of 2026-11-23) (types stay allowed; proven by `test/lint-rules.test.ts`); the context has no `apiKey`, and the key cannot be read or printed from the context (the Authorization header and the dispatcher are private fields of the client, the client a private field of the schema service; `JSON.stringify` and `util.inspect` of the context show neither the key nor its base64 form, tested). Throws `ConfigError` for a domain the client refuses.
- **`src/tools/format.ts`** — untrusted content (SPEC §7.4): `untrusted` puts customer-written text in one `<ticket_content>…</ticket_content>` block (an array or object as its JSON; `null`, numbers and booleans unchanged), with every `<` inside the block, and every entity spelling of it (`&lt`, `&#60`, `&#x3c`, any case, leading zeros, with or without `;`), turned into `‹`, so no delimiter can form whatever invisible character or look-alike letter sits inside the word (a look-alike of `<` itself, such as `＜`, is left as written: it is not the delimiter; in JSON a `<` is written `\u003c` instead, so a `<` parses back the same); `bodyText` takes `body_text` / `description_text` when it is a string, else the HTML converted by `htmlToText` (no parser dependency: comments, script and style dropped, tags removed, entities decoded once, then the same replacement); text over its cap is cut on a code point, with a marker after the block, outside it, giving the count and the caller's way to fetch the rest; `plainName` strips tags from admin-set text (agent and group names, labels, choice names, titles), replaces `<` and its entities the same way and caps it, unwrapped; `fieldValue` wraps a ticket field's value unless its type is a known closed one and the value fits it (number, boolean, ISO date, a choice found in the field's own choices or tree); a status, priority, source, agent or group value goes through `plainName` only as a string or a number. Every pass is linear in the text's length. Applied by the tools that return such text (T-020 onwards); `ticketOutput` itself does not wrap.
- **`src/tools/list.ts`** — list envelope and cursor (SPEC §8.4): `listEnvelope(call, page)` gives `{items, next_cursor?, has_more, truncated?, api_calls_used}`, `has_more` and `next_cursor` together exactly when the tool gives a `next` position, `truncated: true` only when a cap cut the source. A cursor is `<position>.<digest>`: a whole number and an unkeyed SHA-256 (`node:crypto`, base64url) over the tool name, every argument of the call but `cursor` (the raw JSON arguments; any other value, such as a Date, a Map, NaN or a BigInt, throws a `TypeError`), keys sorted, and the position. `readCursor(call, maxPosition?)` runs before any request: a cursor that is not a string, over 64 characters, not of that form, or whose digest does not match this call (another tool, an argument changed, an edited position or digest), or whose position is above the bound the tool passes, is `validation` with `http_status: null`, its message not quoting the cursor; otherwise it returns the position only (0 without a cursor), so no cursor content reaches a URL, host or path. Unkeyed: it catches misuse and edits, not a forged cursor, which can only carry a whole number. Used by the list tools (T-021 onwards).
- **`scripts/smoke/`** — the manual smoke script (SPEC §11, §14 rule 1; T-016), `make smoke`, run by the owner against the real account, never by a test or CI. `smoke.ts`: `SmokeClient`, a subclass of `HttpClient` with no instance field (the base freezes the instance) whose `request` refuses any method but GET before the base sees the call, so nothing is sent, logged or charged to the limiter, and hands the base a copy whose method is GET; `requestWithRetry` goes through `this.request`, so the same guard covers it. `paginate` has a guard of its own: the base builds its first page from the path, query and cost only, so a method given through a cast would go out as a GET instead of being refused. The report gives the shape of `/ticket_fields` (per default field and per custom-field type, the shape of `choices` and counts), whether the zod schemas accepted the three lists, a 2xx that is not JSON told apart from a schema refusal, and the OD-4 line; never a label, name, id, choice, the domain, the key or Freshdesk's text (a failure prints its error code). It refuses to start with `FRESHDESK_HOST_OVERRIDE` set; a configuration error and any unexpected error each print one fixed line. `cli.ts` builds the real undici `Agent`: a second entry point besides the server's future `cli.ts`, which keeps RFC 2026-11-23 rule 2's purpose (only an entry point builds a real dispatcher, and no test imports one: the `**/cli.ts` lint ban in test/** covers this file). Compiled by `tsconfig.smoke.json` into `node_modules/.cache/freshdesk-mcp-smoke/`, out of the tree and of `dist/`; the make target writes a `{"type":"module"}` package.json there and runs Node without syntax detection.
- **`src/config.ts`** — `loadConfig(env)` (SPEC §10): personal settings from the environment (domain, API key, team-file path, custom-domain override), team settings from an optional JSON file under a strict zod schema with defaults (`limits.floor_pct` above `limits.reserve_pct` refused); a `ConfigError` names the variable or the file and key path. Example: `examples/team-config.example.json`.

**Runtime stack** ([RFC 2026-11-23](../rfc/active/2026-11-23-adopt-runtime-stack.md)):
Node ≥ 22.19, `zod ^4.2`, `undici ^8`, `@modelcontextprotocol/server ^2`;
tests on `vitest ^5` with undici `MockAgent`. The HTTP client takes its
dispatcher as a required argument and never uses the global `fetch`.
